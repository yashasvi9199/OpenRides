# Better Comments Styling Rule

Whenever writing code comments, utilize standard human-like phrasing and apply the 'Better Comments' formatting natively:
* `*` highlight/critical info (e.g., `// * Alert: This runs client-side only`)
* `!` warnings/gotchas (e.g., `// ! Warning: Do not run programmatically without closing server`)
* `?` queries/questions (e.g., `// ? Should we extract this to a separate hook?`)
* `TODO` tasks (e.g., `// TODO: Add support for offline sync state`)
* No AI-boilerplate comments or generic descriptions. Comments must look natural and human-written.
